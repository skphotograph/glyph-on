# Glyph-on v1.0 リリース検収

## ビルドと署名

1. WindowsまたはmacOS上で `npm ci` と `npm test` を実行します。
2. Windowsでは管理者が用意したAuthenticode署名環境を、macOSではDeveloper IDと公証用の認証を設定します。認証情報はビルド環境のシークレットに置きます。
3. `npm run dist:release` を実行します。macOSのビルドはアプリの署名と公証チケットを検証します。WindowsではアプリとNSISインストーラーの署名を `Get-AuthenticodeSignature` で確認し、同梱の更新設定に発行者が入っていることを確認します。
4. OSごとにクリーン環境の検収を終え、製品の公開順序、ライセンス、配布経路を確定してから署名済み成果物を公開します。更新メタデータと対象のインストーラーを同じリリースに同梱します。

## macOS公開の必須条件

Chrome、Safari、VS CodeをそれぞれmacOSの標準操作でフルスクリーン化します。既定ホットキーで同じSpaceにAltarが表示され、キーボードとマウスでGlyph選択、Tablet切り替え、Escでの終了を確認できることが合格条件です。閉じたあとも元のアプリとSpaceを維持します。設定、編集、実行確認、ファイルピッカーも実機で開きます。

Spaceのスワイプ切り替え、複数モニターの別Space、倍率差、モニターの取り外し、スリープ復帰、Floating Iconの移動と呼び出しを確認します。ロック・認証画面、排他的フルスクリーンゲーム、DRM保護コンテンツは検収対象から除きます。この試験を通過するまでmacOS正式版を公開できません。

## Windowsと共通の検収

- Explorer、Windowsスタートメニュー、macOS Finderそれぞれのネイティブなドラッグ元から、アプリ、ファイル、フォルダを空スロットに登録します。破損した参照の再指定と代替アイコンを確認します。
- 1366×768以上、100%と200%の倍率、複数モニター、キーボード操作、画面読み上げと高コントラストを試験します。
- 競合するホットキー、複数起動、登録後の再起動、自動起動の切替、起動後に保持される設定を確認します。
- アンインストール時の設定保持と削除をそれぞれ検証します。署名済みの旧版から最新版へ更新し、更新中止と失敗時の再起動で、既存データが保持されることを確認します。
- 計測機のOS、CPU、RAM、ディスプレイ、負荷条件を記録します。起動後の呼び出し30回のp95を200 ms以下、ページ切り替え・編集30回のp95を100 ms以下、コールド起動10回のp95を3秒以下とする提案値を検収します。アイドル10分間の平均CPU利用率1%未満、全プロセスの常駐メモリ200 MB以下も確認します。公開後のクラッシュフリー率は別途定義します。
